Exradius

An open-source, self-hosted platform that runs AI agents on a company's own code. Every task gets its own locked-down Kubernetes pod. The agent works there, asks a person when it needs to, and delivers a branch or a patch.

I designed and built all of it: the API and worker, the Kubernetes operator, the egress proxy, the admin panel and the install.

One run, start to finish

  1. A task arrivesA message on a RabbitMQ queue names a project and an agent. Bridges for Jira and GitHub put it there.
  2. The config is readThe worker reads the project's exradius.yaml from its git repository and creates a Run.
  3. A pod startsAn operator written in Go builds one pod for the run: non-root, read-only filesystem, no capabilities, no cluster credentials.
  4. The agent worksThe runner drives it through the Claude Agent SDK. Its traffic passes an egress proxy that allows only listed hosts.
  5. A person answersThe agent can ask a question through an MCP tool. Once someone answers, the session resumes in the same pod.
  6. The result goes outThe agent pushes a branch or attaches a patch. Status and the result are published as events.

What I built

  • API and worker in Python (FastAPI, PostgreSQL, RabbitMQ). Every state change is stored with its event in one transaction, and the event is published after commit.
  • A Kubernetes operator in Go (controller-runtime) with custom resources for runs and image builds.
  • An egress proxy in Go that adds the model key and repository credentials to requests on the way out, so no pod ever holds them.
  • The runner and its built-in MCP server: ask a person, submit the result, attach files.
  • An admin panel in React and TypeScript.
  • A Helm chart, and Terraform modules for AWS (EKS), GCP (GKE) and Azure (AKS).
  • Secret stores kept encrypted in PostgreSQL or read from HashiCorp Vault.
  • A Claude Code skill that sets a codebase up for Exradius, and an evaluation set of real upstream bug fixes for measuring agents (in progress).

MSc thesis

Which local LLM fits which chat character?

İnönü University, 2026. Official title: Communication Between Interactive Virtual Characters with an AI-Supported Language Learning Application.

Language learners chat with AI characters in the app the thesis proposes: a conversation partner, a language teacher, an emotional-support companion. I investigated which local model is a candidate for each role.

I ran 10 open-weight LLMs (4B to 20B parameters) on the same hardware with Ollama and compared them on four groups of measures: response speed, reliability, linguistic quality and emotion scoring.

I profiled how each model scores 27 emotions on the GoEmotions (Reddit comments), SST-2 (movie reviews) and TweetEval (tweets) datasets.

Across the models, the lowest time to first token was 233 ms, the shortest total response time 2.0 s and the highest generation speed 94 tokens per second.

Models: gemma3:4b, gemma2:9b, llama2:7b, llama3.1:8b, mistral:7b, qwen2.5:7b, granite3.3:8b, olmo2:7b, olmo-3:7b, gpt-oss:20b

Side project

Smart Home Controller AI

A multi-agent system in Python and LangChain.

A coordinator agent reads a natural-language command such as “turn on the kitchen lights and set the temperature to 22 degrees” and routes each part to a specialist agent for lighting or climate. Only the agents a command needs are called, which keeps token cost low.
